# STASYS — Computational Principles
**Lomidze Morphological Algebra (LMA) · External technical explanation · v0.1**

> Audience: systems engineers and technical evaluators. This is a **non-implementation description**, not a publication of proprietary operators or a certification claim.

## What computes the result, if not an LLM?

STASYS investigates **deterministic morphology-native computation** derived from Lomidze Morphological Algebra. In this paradigm, an operational computational structure and its lawfully acquired changes have a causal role in what the system can subsequently express. The response is intended to arise from the system's own state evolution under admitted observations and declared laws, not from a remote generative model or from a host that secretly selects the answer.

In the demonstrated bounded research domains, history-conditioned structural changes and constrained local computation have been evaluated through selective interventions and independently observed consequences. These results **do not** establish universal intelligence, a complete general-purpose perception/navigation system, or a blanket efficiency advantage over conventional software.

### Publishable mathematical abstraction

The canonical Morphic AI **research objective** can be summarized as:

```text
O(t+1) = Phi_G(O(t), E(t))
D(t)   = R(O(t+1))
```

| Term | External engineering interpretation |
|:--|:--|
| `O(t)` | Bounded operative internal state, including structure acquired through previous interactions |
| `E(t)` | Admitted observation or independently confirmed consequence at time/step `t` |
| `G` | Previously declared constitutive laws and resource/admissibility constraints |
| `Phi_G` | Law-constrained **native** state evolution; the external adapter must not calculate the claimed decision |
| `R` | Bounded non-solving readout of the system's own expression |
| `D(t)` | Externally observable typed disposition, before independent authorization/execution |

**Scope of this notation:** a research-level objective and ownership boundary. It is *not* a full mathematical specification of the complete LMA, a public API signature, or proof that every present product component realizes this exact common implementation.

The flight/robot controller retains execution authority. A proposed output and a physically achieved outcome are two different facts.

## How is this different from ML, LLMs or ordinary scripts?

| Question | Defensible answer |
|:--|:--|
| Is this a text model predicting the next token? | No such inference is required for the **native bounded mechanisms studied here**. Some future sensing adapters may still use conventional methods; this package does not claim a completely ML-free sensor chain. |
| Is behavior produced by static case-by-case scripting? | The LMA research requirement is that operative structure and lawfully acquired history causally affect the result, rather than merely naming a scenario or replaying a predetermined answer. |
| Is it impossible to implement an equivalent finite behavior as a state machine? | **No.** Any bounded deterministic trace may be emulated by conventional computation. Novelty and possible value must be tested by mechanism-specific interventions, generalization and measured resource costs. |
| Is the system stochastic or irreproducible? | The studied transitions are deterministic under a declared implementation, complete state and admissible input; cross-platform bit-identity and full flight replay require their own qualification. |
| Does it learn arbitrary semantics or interpret any untrained camera stream? | Not established. The current research has scoped experience-conditioned results, not general-purpose semantic grounding. |

## How are the scientific claims challenged?

- **History comparison:** the same current input is presented after different valid prior experiences; only genuinely causally relevant history may change a subsequent result.
- **Controlled intervention:** selectively changing the operative research substrate must affect the output; a matched sham intervention must not manufacture the same effect.
- **Independent consequence:** only a separately observed environmental result can establish functional success, not a convenient success label emitted by the solver.
- **Matched comparison:** compare against a fully informed conventional method under the same inputs, execution constraints and computational budget.
- **Reproducibility:** fix the tested source/version, conditions, input order and state provenance; replay at the declared fidelity.

These are **research evaluation principles**, not a claim that every listed control is already integrated into a single production package.
