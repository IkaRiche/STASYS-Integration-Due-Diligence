# STASYS — Controlled Black-Box Evaluation Protocol
**Proposed evaluation contract · v0.1 · not an already running service**

## 1. Goal

Let a technically qualified integrator **touch the actual native computation**, choose bounded challenge conditions and independently observe the result **without receiving** STASYS source code, firmware, internal morphology, algebraic operators, unrestricted programmatic query access or platform command authority.

The test objective is to assess a **single integrated system-level commercial hypothesis**: can STASYS materially reduce the complete onboard computing footprint while preserving required useful civil functions and independent safety?

This protocol is proposed. No deployed buyer self-service laboratory, complete multi-function native binary or platform-qualified pilot is asserted here.

## 2. Evaluation boundary

```text
Integrator chooses admissible test case
                |
                v
Fixed public test contract + pinned private native build
                |
                v
Owner-operated isolated execution
                |
                v
External typed inputs/outputs + independent consequence
                |
                v
Signed / committed evidence + baseline comparison
```

**Black-box fidelity rule:** A scripted replay, UI-only visual effect or conventional substitute must never be labeled a live execution of LMA. A permitted test may use a qualified *specific* existing native component; its result cannot be marketed as the complete integrated stack.

## 3. Six acceptance gates

| Gate | Question | Evidence required | Decision |
|:--|:--|:--|:--|
| G0 — Defined scope | Is the exact tested capability already implemented and independently distinguishable from a UI simulation? | Source-owner qualification record, selected build commitment and explicit evidence ceiling | PASS / NOT_READY |
| G1 — Input contract | Are all inputs typed, provenance-bearing and independent of a preselected answer? | Source and validity classes, versioned external envelope | PASS / FAIL |
| G2 — Blind challenge | Does the native implementation respond correctly to permitted integrator-chosen variations? | Exact challenge manifest **fixed before owner-run execution**, sealed results, independent observer | PASS / FAIL / INCONCLUSIVE |
| G3 — Matched controls | Does the test exclude a hidden host solver, cached outputs and cherry-picked positive cases? | Cold/sham/ablation or other source-specific negative controls, plus equal-information conventional comparator | PASS / FAIL / INCONCLUSIVE |
| G4 — Independent consequence | Was useful success established by an independent factual observation, not a component-supplied success flag? | Traceable external measured outcome and corresponding authorization boundary | PASS / FAIL / INCONCLUSIVE |
| G5 — Reproducibility and resources | Can it be repeated, and is resource use lower at comparable useful function? | Build provenance; replay fidelity; memory, latency, power, hardware mass/cost and sample size of **whole system** | PASS / FAIL / INCONCLUSIVE |

A result labeled `PASS_REVIEW_ONLY` is a source/document review, **not** a new independently executed scientific PASS. Empty implementation interfaces are not counted as capability.

## 4. Safe initial demonstrations (existing capabilities first)

### A. Embedded command-path assurance
- **Available donor:** physically tested DRC / STM32 / actual FC telemetry stream.
- **Possible owner-operated demonstration:** a bounded non-actuating bench set with identifiable permitted and denied test messages and a physically separate output observer.
- **Measured externally:** observed forwarding/denial correctness, output timing for the declared firmware/configuration, response to interrupted source observations.
- **No inference:** field-safe flight, complete mission resilience, all-output protection or full-stack consolidation.

### B. Mission-state continuity
- **Available donor:** selected native TMC experiments and a distinct 1,501-state digital session.
- **Possible demonstration:** choose from qualified benign observation/feedback variants; inspect bounded intent/refusal and independently recorded result.
- **No inference:** GNSS-free navigation, physical 25-minute mission completion or generic LMA superiority.

### C. Local digital observation and causal experience
- **Available donor:** qualified scoped Morphic Vision synthetic tests and acquired-state Morphic AI digital experiments.
- **Possible demonstration:** show changes in external disposition under declared local observation change or independently measured different prior experience, with appropriate controls.
- **No inference:** real-camera object tracking, generalized learning or absence of all traditional upstream perception processing.

### D. Leaderless digital cooperation
- **Available donor:** frozen Guardian Veil scoped digital causal line and E006 model-level consequence.
- **Possible demonstration:** verify an existing approved read-only digital evidence viewer against a sealed fixture and its negative controls.
- **No inference:** deployed physical cooperative protection or a verified integrated fleet computer.

**No new combined scientific result is created merely by showing A–D on one dashboard.** Full system-level integration requires its own preregistered experiment with a distinct, legitimate research question.

## 5. Test integrity manifest (external)

Each authorized run should preserve:
- reference to a fixed **claim and acceptance contract**;
- protocol revision, session identifier, target and environmental configuration;
- a rights-holder held build digest and declared compatibility profile;
- evaluator-controlled seed/test parameter commitment where relevant;
- ordered admitted input records with provenance/freshness;
- time bases, reset conditions and independently observed output records;
- authorized/denied operation labels separately from physical consequences;
- exact deterministic replay checks or an explicit reason why replay is partial;
- all attempted cases and controls, including failures, without after-the-fact deletion.

**Do not publish** raw proprietary state, source-adjacent debug data, full private datasets, authorization secrets, security material or sensitive platform configurations.

## 6. Comparative scorecard

Compare complete incumbent vs candidate systems using matched functional scope and admissible observations:

| Metric | Report | Required caveat |
|:--|:--|:--|
| Functional correctness | pass / fail / inconclusive with denominator | Do not report a single session as multiple independent missions |
| Latency | distribution, p50/p95/p99 **if samples measured**, worst observed, jitter | A local compute step is not end-to-end latency or WCET |
| Total power | measured watts by phase / operating state | Include external sensors, adapters and upstream processors still required |
| Mass | measured complete compute/sensor subsystem mass | Do not count a new board alone while omitting supporting compute |
| Memory / storage | Flash, RAM, nonvolatile forensic records | Include buffering, log retention, communications where relevant |
| Reliability | measured failure modes and repeat count | Lab failure coverage is not a universal reliability guarantee |
| Offline reproducibility | exact state/decision replay, divergence localization, source completeness | Hash equality alone is not a causal explanation |
| Cost | complete comparable BOM and integration expense | Avoid declaring financial savings without buyer-provided baseline |

**Comparator:** a fully informed conventional implementation with equal inputs, safety constraints and available resources. If the comparator matches the result, record **parity**; do not claim novelty is a performance lead.

## 7. IP-safe access levels

1. **Owner-operated live review:** the reviewer proposes limited challenge parameters during a supervised session. No compiled artifact leaves owner custody.
2. **Isolated remote evaluation room:** authenticated, time-limited access only after security and contract review; restrict queries, logging, outputs and rate to prevent approximation attacks.
3. **Hardware custody / source audit:** requires a separate written agreement, export/compliance and IP assessment; not authorized by this document.

Even black-box access permits some **behavioral model extraction** through repeated queries. No technical mechanism alone guarantees zero leakage.

## 8. Stop conditions

Stop or mark the result inconclusive if a host supplies the native answer; evidence is replayed as though computed live; recorded outcome is supplied by the same candidate being tested; the comparison omits an expensive external dependency; test cases are rewritten after viewing results; implementation hashes do not match; or evaluation would violate applicable safety/rights constraints.
